# Правила проекта для Claude Code

Сайт-портфолио UX/UI-дизайнера Кирилла Колобанова. Файл читается автоматически при запуске в папке `site/` (`CLAUDE.md` — символическая ссылка сюда), пересказывать правила в промпте не нужно.

Обращение к пользователю — на «Вы», ответы краткие, без вступлений.

## Роли

| Кто | Где | Что делает |
|---|---|---|
| Архитектор | Claude Opus в Cowork | Решения, спецификация `DESIGN.md`, разбор референсов, обработка медиа (ffmpeg, сжатие), аудит |
| Исполнитель | Claude Code (вы) | Код, сборка, git, проверка на живом сайте |

**Если задача требует выбора, которого нет в спецификации — это работа архитектора.** Не выбирайте сами: остановитесь и скажите, что нужно решение. Особенно это касается числовых значений — цвета, размеры, тайминги придумывать запрещено.

## Где что лежит

Репозиторий — только папка `site/`. Уровнем выше, **вне git**, рабочие документы проекта:

- `../DESIGN.md` — спецификация, единый источник истины. Читать перед любой правкой кода.
- `../MASTER_PLAN.md` — фазы и карточки задач с критериями «готово, когда».
- `../JOURNAL.md` — хронология, новые записи сверху, до пяти строк на задачу.
- `../TASKS.md` — статусы.
- `../references/`, `../exports/` — исходники и материалы, в репозиторий не коммитятся.

Эти файлы **не добавлять в `git add`**: они вне репозитория, а один неверный путь отменяет `git add` целиком и даёт пустой коммит.

## Жёсткие правила кода

1. **Спецификация первична.** Значения берутся из `../DESIGN.md` буквально. Код, разошедшийся со спецификацией, — дефект кода.
2. **Ни одного HEX-цвета и ни одного `font-family` вне `src/styles/tokens.css`.** Проверяется `grep` по `src/`. Это условие того, что подмена шрифта после ответа дизайнера останется правкой двух строк.
3. **Пути — только через `withBase()`** из `src/lib/url.ts`. Прямая склейка с `import.meta.env.BASE_URL` запрещена: он отдаёт путь без завершающего слеша, и `${base}media/x.webp` превращается в молчаливый 404 на проде.
4. Размеры из макета 1440 — это **максимумы `clamp()`**, а не константы. Прямая подстановка ломает мобильную вёрстку.
5. Не рефакторить за пределами текущей задачи. Замеченное — в журнал, не в код.

## Ловушки Astro 7, проверенные на этом проекте

- `compressHTML: 'jsx'` по умолчанию: пробелы между инлайн-элементами удаляются. Разделять флекс-отступом, не пробелом в разметке.
- Rust-компилятор строгий: все непустые теги закрывать, невалидную вложенность он не исправляет.
- Content Layer API: путь строится из `entry.id`, поля `slug` нет.
- `src/fetch.ts` — зарезервированное имя, не создавать.
- Markdown-тело (`<Content />`) рендерит Sätteri, не remark. Подключён один
  плагин — `nbspMdastPlugin` (visitor `text` по узлам mdast) в
  `astro.config.mjs`: неразрывные пробелы, DESIGN.md §2, решение архитектора
  02.09.2026. Механизм свой; `@astrojs/markdown-satteri` и `satteri` уже стоят
  как процессор по умолчанию, ничего не устанавливается. Внешние пакеты
  remark/rehype не ставить: `markdown.remarkPlugins` теперь требует установки
  `@astrojs/markdown-remark`, а это лишнее дерево зависимостей.

## Медиа

Файлы — в `public/media/<id кейса>/`, аватар — `public/media/avatar/head.mp4` и `head-poster.webp`. Имена строго такие: файл с другим именем сайт не увидит, и ошибки при этом не будет.

Обработку медиа — сжатие, перекодирование, извлечение постеров — делает архитектор в Cowork: там есть ffmpeg и подобранные параметры. Исходники из нейросетей в репозиторий не класть: они приходят на десятки мегабайт и остаются в истории git навсегда.

## Git

Вы работаете на реальной машине и выполняете git сами, но по правилам:

- Коммит на задачу, не один общий на пакет.
- Перед коммитом показать, что именно в него попадёт.
- В `git add` — только пути внутри `site/`.
- После `git commit` проверить, что в выводе есть строка `[main <хеш>]`. Нет строки — коммита нет, каким бы успешным ни выглядел `push`.
- Работа, не попавшая в коммит, для проверяющего не существует: он смотрит опубликованный сайт. Не откладывать коммит до визуальной проверки.

Сайт: https://proggdd.github.io/job_case_portfolio_k/ — деплой автоматический при пуше в `main`, около полутора минут.

## Проверка

- `npm run build` перед коммитом: сборка проходит без ошибок.
- `npm run dev` для визуальной проверки, смотреть на 375, 768 и 1440 пикселях.
- Консоль браузера чистая.

## Завершение задачи

Отчёт по критериям «готово, когда» из карточки, запись в `../JOURNAL.md` (сверху, до пяти строк), статус в `../TASKS.md`. `../MASTER_PLAN.md` не редактировать — он описывает замысел, а не ход работ.

## Эскалация

Остановиться и вернуть вопрос архитектору, если: нужного значения нет в спецификации; два источника противоречат друг другу; критерий «готово, когда» не выполнен после двух попыток. Третью попытку не делать.
